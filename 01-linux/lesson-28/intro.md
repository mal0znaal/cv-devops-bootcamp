# 28. Bash как язык программирования: от команды до скрипта

Bash приспособлен к запуску программ, передаче аргументов и организации потоков между ними. Главные объекты его мира — команды и текстовые данные. Он отличается от Python именно этим акцентом, а не отсутствием переменных и условий.

## Что делает shebang

~~~bash
#!/usr/bin/env bash
printf 'hello\n'
~~~

Первая строка указывает системе, каким интерпретатором обрабатывать исполняемый текстовый файл. `/usr/bin/env bash` ищет Bash в окружении исполнения. Если явно выполнить `bash script.sh`, программа Bash прочитает файл даже без бита исполнения. Но прямой запуск `./script.sh` требует корректного shebang и разрешения на исполнение.

## Позиционные параметры

`$0` относится к имени скрипта при запуске, `$1` — к первому аргументу, `$2` — ко второму, `$#` — к числу аргументов. Эти значения — строки, которые shell получил после разбора и подстановок командной строки.

~~~bash
#!/usr/bin/env bash
printf 'script=%s\n' "$0"
printf 'model=%s\n' "$1"
printf 'argc=%s\n' "$#"
~~~

Вызов `./run.sh 'my model.pt'` передаёт один аргумент с пробелом. Без кавычек аргументов было бы два.

## Почему "$@" не равно "$*"

Когда обёртка должна передать полученные аргументы другой программе, `"$@"` сохраняет **каждый исходный аргумент отдельно**. `"$*"` внутри кавычек объединяет их в одну строку. Для скрипта, вызывающего `python train.py --weights 'my model.pt'`, ошибка способна сломать поиск файла или изменить интерпретацию параметров.

## Переменные и арифметика

~~~bash
model='yolo v2.pt'
runs=$((3 + 2))
printf 'model=%s runs=%s\n' "$model" "$runs"
~~~

Арифметическое расширение Bash работает с целыми числами; для численной обработки датасетов и моделей разумнее Python. Bash удобен, когда задача заключается в создании каталогов, проверке состояния файлов, обработке кода завершения и запуске внешних программ.

## Функции и состояние shell

~~~bash
show_model() {
    printf 'Model: %s\n' "$1"
}
show_model 'best.pt'
~~~

Функция выполняется в текущем окружении Bash, поэтому может менять переменные оболочки. Команда `return` возвращает **статус** функции, а не произвольный Python-объект.

## Первый проектный скрипт

~~~bash
#!/usr/bin/env bash
project_dir=$1
mkdir -p "$project_dir/models" "$project_dir/logs" "$project_dir/data"
printf 'Prepared: %s\n' "$project_dir"
~~~

Этот пример ещё не проверяет отсутствие аргумента, но показывает связь между позиционным параметром, quoting и идемпотентным созданием каталогов.

## Синтаксис, трассировка и ShellCheck

`bash -n script.sh` проверяет синтаксис без выполнения. `bash -x script.sh` трассирует исполнение, но может раскрыть секреты в диагностическом выводе. ShellCheck находит типичные ошибки quoting и других конструкций Bash.

**Не срезай углы:** проверь скрипт на пути с пробелами и повторном запуске; успешная проверка только на `~/test` ещё ничего не доказывает.
