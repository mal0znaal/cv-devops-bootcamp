# 23. Пакеты Ubuntu: чем apt отличается от dpkg, pip и Docker

Когда пишешь `sudo apt install python3`, система не скачивает произвольный файл «откуда-то из интернета». У неё есть сведения о репозиториях, индексах пакетов, зависимостях, архитектуре и доступных версиях.

## Что такое .deb

Debian-пакет — архив с файлами программы, метаданными и, при необходимости, скриптами сопровождения. В метаданных указаны имя пакета, версия, архитектура и зависимости. `dpkg` устанавливает файлы, учитывает состояние пакета в локальной базе и выполняет соответствующие этапы установки.

## Что делает APT

APT — система более высокого уровня. Она получает индексы репозиториев, выбирает совместимые версии, рассчитывает зависимости и использует механизмы пакетов для установки и обновления. `apt update` **обновляет список доступных пакетов**. Он не обновляет все программы. `apt install` устанавливает запрошенное и зависимости, `apt upgrade` меняет установленный набор согласно политике.

Тебе не нужно делать `apt upgrade` ради решения каждой задачи. На рабочем сервере обновление libc, Python, драйверов и серверных библиотек является изменением среды исполнения.

## Как выяснить владельца команды

~~~bash
command -v ls
dpkg -S /usr/bin/ls
dpkg -s coreutils
dpkg -L coreutils | head
~~~

`ls` — имя команды, `coreutils` — имя пакета, который поставляет её в Debian/Ubuntu. Это разные сущности. `dpkg -s` выводит данные установленного пакета, `dpkg -L` — список файлов, `dpkg -S` — принадлежность пути.

## Candidate и Installed

~~~bash
apt-cache policy coreutils
~~~

Там можно увидеть установленную и кандидатную версии. Они могут отличаться из-за репозиториев и настроек политики APT. Знание версии важно для воспроизводимой сборки и расследования ошибок.

## Системные пакеты и Python

`pip install torch` работает с Python-пакетами. `apt install python3` — с системными пакетами. Их зависимости, пути и механизмы обновления различаются. Установка Python-пакетов в глобальное системное окружение способна конфликтовать с пакетным менеджером; современные дистрибутивы могут защищать system Python через механизм externally managed environments.

Для проекта на Python обычно выбирают виртуальное окружение или Docker-образ с зафиксированными зависимостями. При этом драйвер GPU и системные библиотеки могут оставаться вне области ответственности pip.

## Откуда берётся доверие к репозиторию

APT проверяет подписанные метаданные репозиториев и контрольные суммы пакетов в рамках своей модели доверия. Это не означает, что любой сторонний репозиторий автоматически безопасен. Перед добавлением внешнего источника нужно понимать, кому доверяется право распространять пакеты.

**Не срезай углы:** не добавляй незнакомый PPA и не запускай команду из блога без выяснения источника и нужной версии. Здесь работаем преимущественно с просмотром метаданных.

**Источники:** [Debian Administrator's Handbook — APT](https://www.debian.org/doc/manuals/debian-handbook/), [Ubuntu Package Management](https://ubuntu.com/server/docs/package-management).

## Разбор обновления: один пакет затрагивает другие

Допустим, приложение использует системную библиотеку, а она обновляется вместе с зависимостями. Версия Python-кода осталась той же, но бинарный интерфейс или поведение библиотек изменились. Поэтому воспроизводимость требует фиксировать не только `requirements.txt`, но и базовый образ, системные пакеты и источник их версий.

`apt-cache policy` помогает узнать, откуда пришёл пакет. `dpkg-query` фиксирует уже установленную версию. Это разные вопросы: «что есть сейчас» и «что менеджер выбрал бы для установки».

### Почему обновление индекса не изменяет установленные файлы

`apt update` скачивает метаданные репозиториев, а не новые исполняемые файлы программ. После него версия установленного `coreutils` остаётся прежней, пока отдельная команда установки/обновления не изменит пакет. Это можно проверить: сравни `dpkg-query -W coreutils` до и после чтения индекса в безопасной учебной среде (само обновление индекса может требовать сети и прав).

### Конфликт apt и pip

Если установленный через apt Python управляется дистрибутивом, установка библиотек в глобальные каталоги через pip может нарушить его зависимости. Для проекта используй venv, conda либо контейнер, ясно понимая, какие библиотеки приходят из ОС, а какие из Python package manager.
