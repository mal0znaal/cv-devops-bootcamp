# 25. Сеть из терминала: loopback, интерфейсы, порты, curl

**Время:** ориентировочно 45–90 минут. Отдельные лабораторные создают отдельные Ubuntu VM.

## У адреса есть смысл

`127.0.0.1` — loopback IPv4, обращение к собственной машине. Сервис, слушающий только `127.0.0.1`, обычно недоступен напрямую снаружи. Адрес `0.0.0.0` **при привязке сервера** означает все локальные IPv4-интерфейсы, а не удалённый сервер. Порт (например 8765) помогает ядру направить сетевое соединение нужному сокету.

## Смотреть на сеть, а не только на приложение

`ip -br addr` показывает интерфейсы, `ip route` — маршруты, `ss -ltnp` — TCP-порты в состоянии LISTEN и связанные процессы (часть подробностей требует прав). `curl -v http://127.0.0.1:8765` показывает поведение HTTP-клиента. Успешный TCP connect ещё не гарантирует HTTP 200 и работоспособность модели.

## Что такое сервер в терминах процессов

HTTP-сервер — обычный процесс, который создал слушающий socket и принимает подключения. Если он умер, порт перестанет слушаться. Если он отвечает HTTP 500, процесс жив, но прикладная функция сломана. Если он слушает localhost, запросы с другого хоста могут не доходить до него даже при живом процессе.

## Обратно к ML

Inference API — тот же HTTP-сервер. Позже мы упакуем его в Docker, пробросим порт, добавим Nginx и Prometheus. Нынешнее понимание bind-address и портов будет базой для каждого последующего шага.

**Не срезай углы:** не меняй bind на 0.0.0.0 только ради того, чтобы заработал чужой curl. Сначала разберись, откуда идёт запрос и какой адрес слушается. [ip(8)](https://man7.org/linux/man-pages/man8/ip.8.html).
