# Устрани неисправность и проверь результат

Ты уже установил, что клиент получает HTTP 404 при работающей службе. Теперь сопоставь фактическую конфигурацию процесса с тем, что существует на диске, и найди несоответствие.

Действуй так: сформулируй гипотезу → проверь её по файлам, настройкам и журналу → внеси **одно минимальное изменение** → повтори HTTP-запрос. Если изменял unit-файл, перечитай его через `systemctl daemon-reload` и перезапусти службу.

Ожидается активный `cvbootcamp33.service`, пользователь службы `nobody`, HTTP 200 и точный текст `CV-SERVICE-READY`.

В `~/lab33/fix.txt` напиши объяснение длиной не менее 70 символов: какой параметр оказался неправильным, с чем ты сравнил его значение, что изменил и почему после этого HTTP стал отвечать правильно.

**Не срезай углы:** не создавай дополнительную копию страницы в случайной директории только для зелёной проверки, не меняй `User=nobody` на root и не используй `chmod 777`.
