# Зафиксируй отказ до изменений

Проверь последовательно состояние службы, наличие слушающего TCP-порта и фактический HTTP-ответ:

```bash
systemctl status cvbootcamp33.service
ss -ltnp
curl -i http://127.0.0.1:8873/
```

Найди HTTP-статус в выводе `curl`. При подготовленном для этой лабораторной состоянии сервер должен отвечать 404. Это не готовый диагноз: ответ 404 не говорит, почему страница не найдена.

В `~/lab33/initial.txt` зафиксируй три наблюдения, по одному на строку:

```text
unit=active
port=8873
http=404
```

Сравни показания `systemctl` и `curl`. Почему они могут одновременно быть правильными?

Затем прочитай `systemctl cat cvbootcamp33.service` и посмотри файлы в `/opt/cvbootcamp33`. **На этом шаге ничего не редактируй**. Собери хотя бы две гипотезы о причине HTTP 404 и реши, какой командой проверишь каждую.
