# 11. Поиск файлов через find: дерево каталогов и предикаты

`find` ищет пути, удовлетворяющие условиям, при обходе дерева файловой системы. `grep` ищет строки внутри файлов. Это два разных типа поиска, хотя их нередко соединяют в pipeline.

## Откуда find берёт результаты

Команда `find ~/project -type f -name '*.pt'` начинает обход с `~/project`, посещает вложенные каталоги и проверяет каждый найденный объект. Условие `-type f` означает обычный файл; `-name '*.pt'` проверяет имя относительно glob-шаблона, но **сам шаблон интерпретирует find**, а не Bash — если ты оставил его в кавычках.

~~~bash
find ~/project -type f -name '*.pt'
~~~

Без кавычек текущая оболочка может раскрыть `*.pt` по содержимому собственной директории. Тогда `find` получит совершенно другие аргументы и может завершиться ошибкой.

## Предикаты и действия

`-type d` выбирает директории, `-iname` игнорирует регистр в имени, `-size` фильтрует по размеру с правилами округления, `-mtime` — по возрасту модификации, `-maxdepth` ограничивает глубину обхода в GNU find. Каждая опция означает конкретное условие, а не абстрактное свойство поиска.

`-print` печатает совпадающие пути. `-exec` запускает другую команду для найденных объектов. `-delete` **удаляет** совпадения, поэтому применять его без предварительной проверки результата крайне опасно.

## Что значит «путь безопасен для скрипта»

Имя файла Linux может содержать пробелы, табы и даже символ перевода строки. Поэтому такой код ненадёжен:

~~~bash
for file in $(find . -type f); do
    printf 'file: %s\n' "$file"
done
~~~

Bash разделит полученный текст по пробелам и переводам строк; границы реальных имён потеряются. Для надёжной обработки в программах предусмотрены NUL-разделители: `find ... -print0` и совместимые с ними инструменты вроде `xargs -0`. В Bash существуют циклы чтения с `read -r -d ''`. Полноценные шаблоны изучим позже.

## Почему find важен при работе с ML

В проекте могут оказаться несколько версий `best.pt` в разных каталогах, конфиги `config.yaml` рядом с датасетами и логи нескольких запусков. Прежде чем удалить старые checkpoints, нужно точно установить их расположение и дату изменения. Самого имени `best.pt` недостаточно — важен путь.

## Эксперимент

Создай два файла моделей в разных папках, а рядом — обычные .txt. Проверь `find . -type f -name '*.pt'`. Измени глубину поиска через `-maxdepth` и предскажи, какие модели исчезнут из результатов.

**Не срезай углы:** сначала собирай и проверяй список файлов. Не дописывай `-delete` и `-exec rm` к команде, смысл фильтра которой не проверен.
