# 12. Текстовые конвейеры: sort, uniq, cut, tr и tee

В Unix небольшие программы удобно связывать стандартными потоками. Каждая утилита выполняет ограниченную задачу, а pipe передаёт её stdout следующей. Такая композиция особенно полезна при просмотре логов, быстрой статистике и отладке конфигураций.

**Локаль (locale)** — настройки языка и правил обработки текста, в том числе сортировки и преобразования регистра. Переменная `LC_ALL` при наличии значения переопределяет отдельные категории локали. Значение `C` использует простой порядок, удобный для воспроизводимых технических результатов; это не «правильный алфавитный порядок» для любого языка.

## sort и вопрос порядка

`sort` сортирует строки по выбранному правилу сравнения. Порядок зависит от локали; для предсказуемой байтовой сортировки в скриптах часто используют `LC_ALL=C sort`. После сортировки исходная хронология записей потеряется, если ты не сохранил оригинал.

~~~bash
printf '500\n200\n500\n404\n200\n' | sort
~~~

В результате одинаковые коды окажутся рядом.

## uniq не удаляет все дубликаты произвольного файла

`uniq` сравнивает **соседние** строки. Если одинаковые записи разделены другими, он не считает их одним повтором. Чтобы сгруппировать одинаковые значения, обычно применяют `sort | uniq -c`:

~~~bash
printf '500\n200\n500\n404\n200\n' | sort | uniq -c
~~~

`-c` добавляет число повторений. Но сортировка изменила порядок; если важна временная последовательность инцидентов, такую цепочку нельзя выдавать за исходный лог.

## cut и поля

`cut -d, -f2 file` выбирает второе поле, разделённое запятой. Простой инструмент не умеет интерпретировать CSV-кавычки как полноценный парсер. Строка `a,"b,c",d` содержит поле с внутренней запятой, которую `cut` ошибочно примет за разделитель. Для настоящего CSV используй Python `csv`.

## tr

`tr` читает символы из stdin и заменяет либо удаляет их по заданным наборам:

~~~bash
printf 'hello\n' | tr '[:lower:]' '[:upper:]'
~~~

Для преобразования текста он удобен, но сложные правила Unicode и локали требуют осторожности.

## tee

`tee` пишет один поток одновременно в stdout и файл:

~~~bash
printf 'model loaded\n' | tee /tmp/model.log
~~~

Обычный `>` отправил бы stdout только в файл и ничего не показал в терминале. `tee` сохраняет оба направления. `tee -a` добавляет записи к существующему файлу; без `-a` он обычно перезаписывается.

## Разбирай pipeline по этапам

Если `sort | uniq -c | sort -nr` даёт неожиданное число, запускай шаги слева направо: сначала сортировку, потом группировку, затем итоговую сортировку. Сложная цепочка становится понятной, когда знаешь промежуточные данные.

**Не срезай углы:** не запоминай весь pipeline как одно заклинание. Объясни вход и выход каждой программы.

**Источники:** [GNU Coreutils — sort](https://www.gnu.org/software/coreutils/manual/html_node/sort-invocation.html), [uniq](https://www.gnu.org/software/coreutils/manual/html_node/uniq-invocation.html), [tee](https://www.gnu.org/software/coreutils/manual/html_node/tee-invocation.html).

## Углубление: контракт каждого фильтра

Пусть вход содержит последовательность событий: `200, 500, 200, 404, 500, 200`. `sort` меняет порядок строк. `uniq -c` считает соседние группы. В цепочке `sort | uniq -c` одинаковые строки собраны вместе, поэтому частоты получаются правильными. Но хронология событий при этом теряется: нельзя по отсортированному выводу выяснить, шли ли ошибки 500 подряд.

Текущая локаль может влиять на порядок `sort`. Для воспроизводимого технического сортирования иногда задают `LC_ALL=C`. Это байтовый порядок, а не правило, подходящее для любой человеческой сортировки слов.

~~~bash
printf 'alice,200\nbob,500\n' | cut -d, -f2
~~~

`cut` выделяет поля по разделителю, но не понимает полноценный CSV со вложенными кавычками. Для сложного CSV нужен Python `csv`.

~~~bash
printf 'run=1\nrun=2\n' | tee /tmp/runs.log | wc -l
~~~

`printf` создаёт байты, `tee` сохраняет копию и отправляет их дальше, `wc` считает переводы строк. Сравни содержимое `/tmp/runs.log` с итоговым числом. Если один элемент цепочки непонятен, запускай цепочку по частям.
