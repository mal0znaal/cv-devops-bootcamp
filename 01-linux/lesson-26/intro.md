# 26. SSH: ключи, клиент, known_hosts и безопасный доступ

**Время:** ориентировочно 45–90 минут. Отдельные лабораторные создают отдельные Ubuntu VM.

## SSH — не просто команда для подключения

SSH создаёт защищённый канал между клиентом и удалённым сервером: проверяется ключ сервера, выполняется аутентификация пользователя, затем запускается shell либо отдельная команда. Он нужен для доступа к Linux-машинам, Git, деплоя CI/CD, туннелей и передачи файлов.

## Ключ клиента и ключ сервера

Пара ключей пользователя (`ssh-keygen`) состоит из **приватного**, который нельзя публиковать, и публичного, который можно добавить в `authorized_keys` разрешённого сервера. У сервера тоже есть host key; SSH-клиент сохраняет сведения о нём в `known_hosts`. Проверка отпечатка сервера защищает от подключения к неожиданной машине. Не лечи проблемы массовой опцией `StrictHostKeyChecking=no`.

## Практическая анатомия команды

`ssh -i ~/.ssh/id_ed25519 user@host -p 2222` задаёт ключ, пользователя, хост и порт. `~/.ssh/config` позволяет писать имена хостов и параметры один раз. `ssh -G name` показывает итоговую конфигурацию клиента **без подключения**, что удобно для учебного эксперимента.

## Агент и пароли

`ssh-agent` может хранить расшифрованные ключи в памяти для сеанса, но не должен превращаться в универсальный обход защиты. Для CI/CD обычно используют отдельные деплой-ключи с минимальными правами и ограничениями.

**Здесь нельзя срезать углы:** приватный ключ никогда не вставляй в GitHub, скриншот или ответ чата. Проверку host key не отключай ради удобства. [OpenSSH manuals](https://www.openssh.com/manual.html).
