# 17. Владелец файла, группа, sudo и запуск приложения без root

`chmod` меняет права доступа, `chown` — владельца и группу. При ошибке открытия файла важно установить, какой именно пользователь выполняет операцию и какие права назначены на каждом элементе пути.

## Владелец не означает создателя навечно

У файлового объекта хранятся UID и GID владельца. Обычно файл получает UID процесса, который его создал, но владение можно изменить с достаточными правами. `stat -c '%U %G %a' file` покажет имя владельца, группу и режим.

Если файл создан через `sudo`, владельцем нередко становится root. Потом Python-скрипт обычного пользователя пытается записать туда лог и получает `Permission denied`.

## sudo — запуск конкретной команды с другими правами

`sudo command` запускает команду с правами, определёнными политикой sudoers. Повышение относится к указанному процессу и его потомкам, а не автоматически ко всем операциям текущего shell. Поэтому `sudo echo text > /root/output` может завершиться ошибкой на операторе `>`, который выполняет обычный Bash.

`sudo -u nobody command` позволяет, при наличии разрешения, проверить запуск от непривилегированного пользователя. Такой тест часто полезнее, чем запускать сервис root «для проверки».

## Что делает chown

~~~bash
stat -c '%U:%G' ~/lab17/data.txt
~~~

`chown user:group file` меняет владельца и группу. Для изменения UID обычно требуются повышенные привилегии. `chgrp` меняет группу, если у пользователя есть на это права.

Не надо менять владельца системного каталога целиком. Особенно опасен `chown -R` на путях, которые могут содержать данные других служб.

## Отладка прав как причинная цепочка

Допустим, сервис под `User=mlapi` не может читать `/srv/models/yolo.pt`. Проверяем: существует ли файл, доступен ли `/srv` для прохождения, каков режим `/srv/models`, кому принадлежит модель и какие группы у `mlapi`. После этого меняем минимальное свойство, например группу файла и права на чтение.

Это точнее и безопаснее, чем открыть весь путь для записи всем пользователям.

## Принцип минимально необходимых привилегий

Inference-сервису достаточно читать модель, принимать запросы на конкретном порту и записывать свои временные данные в разрешённую директорию. Ему не нужны права устанавливать системные пакеты, менять ядро или редактировать чужие файлы. Эту модель можно реализовать через отдельную учётную запись и systemd-опции.

**Не срезай углы:** на учебной VM root допустим для настройки системы, но в unit конечного приложения используй отдельного пользователя. Не удаляй ограничения только ради зелёного CHECK.
