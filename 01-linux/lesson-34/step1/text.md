# 01. Исследуй работу приложения до исправления

Проверь `systemctl status cvbootcamp34.service`, слушающий порт через `ss -ltnp` и фактический запрос:

```bash
curl -i http://127.0.0.1:8874/health
```

Подготовленная лабораторная должна вернуть HTTP 503 с JSON-статусом `not_ready`. Этот ответ означает, что сервер работает и дошёл до прикладной проверки; конкретную причину ещё предстоит установить.

Сохрани наблюдения в `~/lab34/before.txt`:

```text
service=active
http=503
port=8874
```

Изучи unit через `systemctl cat`, Python-файл и дерево `/opt/cvbootcamp34`. Определи, что именно проверяет endpoint `/health` и какие данные требуются для успешного ответа.

**Пока ничего не меняй.** Сначала запиши собственное объяснение, какие возможны причины `not_ready` и чем их можно различить.
