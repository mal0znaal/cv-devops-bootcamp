# 01. Исследуй систему, не меняя её

Проверь фактические состояние и HTTP-код, затем создай `~/lab34/before.txt`:

```text
service=active
http=503
port=8874
```

Это **наблюдение до исправления**. Если видишь другой код, разбирайся, не продолжай вслепую. Не модифицируй unit-файл на этом шаге.

---

**CHECK** проверяет состояние, но не заменяет твой собственный разбор причин.

## Определи, на каком уровне отказ

Убедись, что `curl -i http://127.0.0.1:8874/health` вернул JSON с `not_ready` и HTTP 503. Само наличие JSON означает, что код Python дошёл до обработчика запроса.

Теперь сравни путь модели из переменной `CV_MODEL_PATH` и `WorkingDirectory` в unit. Пока только читай данные. Попробуй мысленно вычислить абсолютный путь, который получается при их сочетании, и сравни с фактическим файлом через `find /opt/cvbootcamp34 -type f`.

**Где не срезать углы:** не меняй `app.py`, не создавай вторую копию модели в неверном каталоге и не пиши в before.txt придуманный статус.
