# 02. Проверь гипотезу и восстанови API

На основании собранных данных найди причину, по которой Python не может пройти проверку готовности модели. Сравни параметры запуска процесса, его рабочую директорию, переменные окружения, положение файла и права сервисного пользователя.

Исправь **одну** настройку, которая объясняет исходный HTTP 503. Исходный `app.py` и файл модели менять нельзя; запускать службу под root тоже не нужно.

Если меняешь systemd unit, выполни `systemctl daemon-reload`, затем `systemctl restart cvbootcamp34.service`. Проверь:

```bash
systemctl is-active cvbootcamp34.service
curl -i http://127.0.0.1:8874/health
```

Результат — HTTP 200 и JSON, содержащий `"status": "ready"`.

Если ответ не изменился, снова проверь собственную гипотезу. Не меняй одновременно три независимые настройки, иначе невозможно понять, какая из них помогла.
