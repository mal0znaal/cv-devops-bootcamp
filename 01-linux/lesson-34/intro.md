# 34. Финальная миссия: inference-сервис возвращает HTTP 503

В учебном окружении есть Python HTTP-сервер. Вместо настоящей нейросети он загружает небольшой файл модели и отвечает на `/health`. Такая имитация сохраняет главное свойство настоящего CV-сервиса: процесс может быть запущен, а модель — недоступна.

## Контракт учебного API

При запросе `GET /health` приложение проверяет, существует ли ожидаемый файл модели и не пустой ли он. Если проверка успешна, возвращает HTTP 200 и JSON со статусом `ready`. Если нет — HTTP 503 и `not_ready`.

Это решение реализует **само Python-приложение**. Ни ядро, ни systemd не знают, что для этого API означает «модель готова».

## Относительный путь

Конфигурация содержит переменную окружения вроде `CV_MODEL_PATH=models/model.bin`. Это относительный путь: Python разрешает его относительно текущей рабочей директории процесса. `WorkingDirectory=` в unit задаёт эту директорию при запуске.

Модель может лежать в `/opt/cvbootcamp34/models/model.bin`, но процесс с рабочим каталогом `/opt/cvbootcamp34/logs` будет искать `models/model.bin` внутри папки логов. Файл модели существует — и всё равно не найден приложением. Оба факта совместимы.

## Дополнительная проверка прав

Наличие правильного пути недостаточно, если у пользователя сервиса нет права пройти по родительским директориям или читать файл. Используй `namei -l`, `stat`, `id` и посмотри `User=`. Не надо исправлять ошибку расширением прав до 777: сначала докажи, что отказ связан именно с ними.

## Раздельные показатели

`systemctl is-active` говорит о состоянии unit. `ss -ltnp` — о слушающем TCP-сокете. `curl -i /health` — о результате прикладной проверки. Именно последняя команда указывает, может ли приложение выполнить критически важное условие загрузки модели.

## Как провести расследование

Сними HTTP 503 и запиши его вместе с временем. Прочитай unit, проверь `WorkingDirectory` и `CV_MODEL_PATH`, затем фактическое расположение модели. Запиши гипотезу. Меняй только параметр, ответственный за несоответствие. Сделай `daemon-reload` и `restart`. Повтори `curl` и проверь одновременно HTTP 200 и содержимое JSON.

## Healthcheck как исполняемый контракт

`health.sh` должен выполнить настоящий HTTP-запрос и завершиться ненулевым кодом при ошибке соединения или 5xx-ответе. `echo ready` с `exit 0` технически проходит как успешная команда, но бесполезен как диагностика.

## Что нужно оставить после исправления

В `runbook.md` запиши исходный статус, неверно разрешавшийся путь, фактическую рабочую директорию, изменение в unit, финальный HTTP-ответ и способ повторной проверки. Следующий инженер должен понять решение без чтения истории терминала.

**Не срезай углы:** не меняй Python-код, файл модели и сервисного пользователя ради получения зелёного CHECK. Цель — найти причину на уровне конфигурации запуска.
