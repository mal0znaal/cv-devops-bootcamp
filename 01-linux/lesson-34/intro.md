# 34. Финальная миссия: восстанови CV inference API

# Финальная миссия — это экзамен по всему модулю, не «ещё одно упражнение»

Тебе достался учебный inference-сервис на Python. Он не использует GPU и не исполняет YOLO — вместо модели лежит файл `models/model.bin`, а сервер по пути `/health` сообщает, может ли его увидеть. Это **имитация реальной проблемы** совместимости путей и окружения, а не обещание GPU в Killercoda.

Сервис запускается через `systemd`, работает от непривилегированного пользователя, слушает `127.0.0.1:8874`. В репозитории учебной VM подготовлены скрипт, файл модели и unit. Но после запуска healthcheck сообщает, что модель недоступна.

## Как следует подходить к задаче

**Первый круг — только наблюдение.** Проверить `systemctl status cvbootcamp34`, `journalctl -u cvbootcamp34 -n 30 --no-pager`, `ss -ltnp`, `curl -i http://127.0.0.1:8874/health`, `systemctl cat cvbootcamp34`, содержимое `/opt/cvbootcamp34` и права `stat`.

**Второй круг — построить причинную модель.** Что такое текущая рабочая директория процесса? Как она влияет на относительные пути внутри Python? Как конфигурируется environment у systemd? Доступен ли файл пользователю сервиса?

**Третий круг — минимальное изменение.** Исправь именно причину, не меняя несколько параметров одновременно. Можно выбрать обоснованное решение через WorkingDirectory либо корректный абсолютный путь в CV_MODEL_PATH. Затем reload/restart, запрос `/health`, фиксация результата.

**Четвёртый круг — профилактика.** Сделай исполняемый healthcheck-скрипт и запиши короткий runbook.

## Правила финальной миссии

- Не используй `chmod 777`.
- Не переводь systemd-сервис на root.
- Не изменяй `app.py` и `models/model.bin` ради обхода проверки.
- Не заменяй настоящий HTTP-healthcheck командой `echo OK`.
- Можно читать документацию, `--help` и `man`. Это *обязательная* часть навыка, не читерство.

**Документация:** [systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html), [systemd.service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html), [curl docs](https://curl.se/docs/).
