# 34. Финальная миссия: Python-сервис сообщает, что не готов

В учебной машине работает Python HTTP API, имитирующий проверку загруженной модели. Он не выполняет YOLO: при запросе `GET /health` проверяет доступность небольшого файла и возвращает JSON.

При успешной проверке клиент получает HTTP 200 и `{"status": "ready", ...}`. Когда прикладная проверка не проходит — HTTP 503 и `not_ready`. Это поведение написано в приложении; ни ядро Linux, ни systemd не знают, что именно считается готовностью модели.

**JSON (JavaScript Object Notation)** — текстовый формат структурированных данных. В нём объект с полем `status` может выглядеть как `{"status": "ready"}`. Тело HTTP-ответа содержит эти данные; код HTTP 200 или 503 передаётся отдельно от JSON в строке статуса.

## Твоя задача

Установи, почему `http://127.0.0.1:8874/health` не возвращает ожидаемый результат. Доступны исходный код `/opt/cvbootcamp34/app.py`, подготовленные данные в `/opt/cvbootcamp34` и unit `cvbootcamp34.service`.

Перед изменениями собери свидетельства:

```bash
systemctl status cvbootcamp34.service
systemctl cat cvbootcamp34.service
journalctl -u cvbootcamp34.service -n 30 --no-pager
ss -ltnp
curl -i http://127.0.0.1:8874/health
```

Не считай, что живой PID гарантирует успешный HTTP. Не считай, что правильный HTTP-порт гарантирует доступность модели.

## Как проверять гипотезы

Если подозреваешь ошибку пути, выясни **фактический рабочий каталог процесса** и место, где лежит нужный файл. Относительный путь разрешается относительно рабочей директории, а `WorkingDirectory=` — один из параметров systemd, способных на это влиять.

Если подозреваешь права, посмотри `User=`, режим самого файла и возможность проходить через все директории пути. Если подозреваешь переменные окружения, выясни, что задаёт unit и что использует Python-код. Преждевременно менять все три вещи сразу бессмысленно.

Формулировка гипотезы должна содержать проверяемое предсказание. Например: «если приложение ищет файл не в той директории, то проверка абсолютного пути обнаружит реальный файл, а вычисленный относительный путь не существует».

## Что считается решением

После **одного обоснованного исправления** endpoint должен возвращать HTTP 200 и `"status": "ready"`. Служба должна продолжать работать под непривилегированным пользователем. Сам `app.py` и подготовленные данные модели изменять не нужно.

Затем напиши `health.sh`, который действительно опрашивает HTTP и возвращает ненулевой код, когда проверка не проходит. Проверь скрипт в двух состояниях: когда сервис работает и когда он недоступен. Запиши в runbook причину отказа, доказательства и способ проверить исправление.

Документация: [systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html), [curl](https://curl.se/docs/).
