# 02. Как Bash превращает набранный текст в выполняемую команду

На экране терминала ты набираешь `mkdir -p project/data`. На первый взгляд всё просто: первое слово — имя программы, второе — флаг, третье — путь. Но оболочка прежде всего должна разобраться, где заканчивается одно слово и начинается другое, какие символы имеют специальный смысл, что следует заменить значением переменной и какую программу запускать.

## Строка команды — не предложение естественного языка

Операционная система не «понимает» `mkdir -p`. Bash читает строку и разбирает её по грамматике shell. В простом случае команда содержит имя программы и аргументы. Запущенная программа получает массив строк `argv`: `argv[0]` обычно содержит её имя, последующие элементы — аргументы. В Bash между словами важны кавычки, пробелы и специальные операторы.

Например:

~~~bash
printf '%s\n' alpha beta
printf '%s\n' 'alpha beta'
~~~

В первом случае `printf` получает два аргумента после строки формата, во втором — один аргумент с пробелом. Разница возникла **до** того, как `printf` начал печатать текст.

Сочетание `-p` — просто строка аргумента. Программа `mkdir` сама решает, что оно означает. У `mkdir -p` это создание недостающих родительских каталогов. У `ssh -p 2222` — номер порта. Нельзя выучить «`-p` означает parents» как универсальное правило Linux.

## Как Bash находит команду

Когда имя команды не содержит `/`, оболочка рассматривает свои определения и встроенные команды, а для внешних программ выполняет поиск по `PATH`. `PATH` — последовательность директорий, разделённых двоеточиями:

~~~bash
printf '%s\n' "$PATH"
type -a ls
command -v ls
type -P ls
~~~

Предположим, `PATH=/usr/local/bin:/usr/bin:/bin`. Поиск бинарника `python3` выполняется по этим директориям в установленном порядке. Bash также кеширует результаты поиска в hash-таблице; проверить можно через `hash`, очистить — `hash -r`.

Если команда содержит слеш, например `./train.sh` или `/usr/bin/python3`, поиск по `PATH` не нужен: путь назван явно. Точка в `./train.sh` означает текущую директорию. Именно поэтому запуск `train.sh` может дать `command not found`, а `./train.sh` выполнится.

## Почему cd — встроенная команда

У каждого процесса есть текущая рабочая директория. Когда Bash запускает внешнюю программу, та наследует начальную рабочую директорию. Если программа изменит её и завершится, родительский Bash не обязан менять собственную рабочую директорию.

`cd` должна изменить состояние **текущего** Bash, поэтому реализована как builtin. Проверь:

~~~bash
type cd
type pwd
pwd
cd /tmp
pwd
~~~

`pwd` также бывает builtin и отдельным исполняемым файлом. Команда `type -a pwd` покажет варианты, а `/bin/pwd` явно запустит внешнюю программу, если этот путь существует.

## Команды, функции, алиасы

Shell-функция — программа из команд Bash, выполняющаяся внутри окружения оболочки. Алиас — текстовая подстановка при разборе командной строки в определённых условиях. Например, в пользовательских настройках можно встретить `alias ll='ls -alF'`. Но `ll` не обязан существовать на другой машине: это не стандартная команда Linux.

Для выяснения природы команды пользуйся `type name`, а не только `which name`: `which` обычно ищет исполняемые файлы и не обязан корректно описывать функции и builtins.

## Что значат exit status и $?

После завершения команда возвращает код. Ноль — традиционный сигнал успеха; ненулевые значения сообщают об ошибках или специфическом исходе, например об отсутствии совпадений у `grep`.

~~~bash
test -f /etc/os-release
echo $?
test -f /no-such-file
echo $?
~~~

`$?` — специальный параметр Bash, содержащий статус **последней** команды. Если между проверяемой командой и `echo $?` ты успел запустить другую, увидишь код другой команды.

Коды выхода позволяют строить условия: `if test -f file; then ...; fi`. Они важнее, чем наличие слов «success» в stdout. Сервис может напечатать красивое сообщение и завершиться с ошибкой.

## Где появляются кавычки и спецсимволы

Одинарные кавычки запрещают почти все расширения Bash, двойные сохраняют пробелы, но разрешают раскрытие переменных и некоторые другие операции. Символ `*` может раскрываться в список файлов. `>` — вообще **оператор оболочки**, а не строковый аргумент `echo`. Детальные правила изучим в уроках 5, 8 и 9, но главное различие уже видно: не всё, что ты написал в терминале, передаётся запущенной программе.

## Почему сообщение command not found не всегда означает отсутствие пакета

Причины бывают разными: нет бинарника, неверный `PATH`, опечатка, попытка запустить локальную программу без `./`, неработающий shebang, неверная архитектура исполняемого файла. Команда `type -a` показывает лишь один слой диагностики. Проверяй путь и метаданные файла, прежде чем советовать `sudo apt install`.

## Эксперимент без подсказки с готовым ответом

1. Сделай `type cd` и `type ls`. Кто выполняет первую команду, а кто вторую?
2. Сравни `printf '%s\n' "model v2.pt"` и `printf '%s\n' model v2.pt`. Подсчитай, сколько аргументов передано.
3. Выполни `false; echo $?` и `true; echo $?`. Почему результаты различаются?
4. Проверь `command -v python3`, затем попробуй запустить найденный путь явно.
5. Через `mkdir --help` выясни значение `-p`. Затем повтори `mkdir -p ~/experiment/a/b` два раза и объясни, почему оба вызова проходят.

**Где не стоит срезать углы.** Не угадывай назначение флага по одной букве и не считай shell просто клавиатурой для ядра. На реальном сервере неправильное раскрытие аргументов способно удалить файлы или испортить параметры деплоя.
