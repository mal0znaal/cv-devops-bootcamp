# 09. Кавычки, переменные и подстановки: почему shell «портит» аргументы

Типичная ошибка в ML-скрипте: путь `/data/my models/yolo.pt` передаётся программе как два аргумента. Для исправления недостаточно механически поставить кавычки — нужно знать, на каком этапе Bash разделяет строки и раскрывает выражения.

## Как shell обрабатывает слова

Bash сначала распознаёт синтаксис строки. Затем он выполняет несколько видов расширений: фигурные скобки, тильду, переменные, командную и арифметическую подстановки, word splitting, filename expansion и снятие служебных кавычек. Порядок оговорён в Bash Reference Manual.

~~~bash
file='my model.pt'
printf '<%s>\n' $file
printf '<%s>\n' "$file"
~~~

В первой команде `$file` без кавычек превращается в два слова. Во второй `"$file"` остаётся **одним аргументом**. Это можно проверить по количеству строк, которые печатает `printf`.

## Одинарные кавычки

`'$HOME'` содержит буквальные символы доллара и имени переменной. Bash не раскрывает переменные внутри одинарных кавычек:

~~~bash
printf '%s\n' '$HOME'
~~~

Они удобны для регулярных выражений, шаблонов awk и текстов, которые нельзя менять при разборе.

## Двойные кавычки

`"$HOME"` раскрывает переменную и сохраняет полученную строку как один аргумент. Внутри двойных кавычек работают переменные и `$(command)`. Пример:

~~~bash
name='CV engineer'
printf '%s\n' "Hello, $name"
~~~

В программах, работающих с путями, переменные пути почти всегда стоит брать в двойные кавычки: `cp "$source" "$destination"`.

## Специальные параметры Bash

`$?` хранит статус последней команды, `$$` — PID текущей оболочки в соответствующем контексте, `$1` и `$2` — позиционные аргументы скрипта, `$#` — их количество. `"$@"` разворачивает все позиционные аргументы как **отдельные значения**, что существенно при передаче аргументов другой программе.

## Переменные shell и окружение процесса

`name=value` создаёт/меняет переменную текущего shell. `export name` помечает её для передачи новым дочерним процессам. Одноразовая запись `MODE=test python3 app.py` устанавливает значение для конкретного запуска.

Процесс не видит произвольные неэкспортированные переменные родительского Bash. Поэтому переменная, работающая в терминале, может отсутствовать в systemd-сервисе: его окружение формируется независимо.

## Подстановка результата команды

~~~bash
today=$(date +%F)
printf 'Today: %s\n' "$today"
~~~

Bash запускает `date`, забирает stdout и подставляет полученный текст. Это отличается от обычной строки: код **выполняется**. Поэтому нельзя запускать неизвестные shell-строки из непроверенного источника.

## Арифметика

~~~bash
count=$((2 + 3))
printf '%s\n' "$count"
~~~

В арифметическом контексте Bash работает с целыми числами. Он не является заменой Python для численных вычислений или работы с float.

## Почему разделение и glob связаны

Незакавеченное раскрытие переменной может привести не только к splitting, но и к подстановке файлов по `*`. Если переменная содержит символы glob-шаблона, при определённых условиях программа получит неожиданный список файлов. Кавычки защищают не только пробелы.

## Эксперимент с Python

~~~bash
python3 -c 'import sys; print(sys.argv)' 'model v2.pt'
python3 -c 'import sys; print(sys.argv)' model v2.pt
~~~

`sys.argv` напрямую покажет, какие аргументы получил Python. Это лучший способ проверить, что Bash действительно передал программе.

**Не срезай углы:** не ставь кавычки по принципу «так принято». Предсказывай, как изменится массив аргументов без кавычек, в одинарных и в двойных.

**Источники:** [Bash Shell Expansions](https://www.gnu.org/software/bash/manual/html_node/Shell-Expansions.html), [Bash Quoting](https://www.gnu.org/software/bash/manual/html_node/Quoting.html).

## Углубление: как увидеть реальные аргументы программы

Запусти:

~~~bash
python3 -c 'import sys; print(repr(sys.argv))' one 'two words'
python3 -c 'import sys; print(repr(sys.argv))' one two words
~~~

Во втором случае Python получил на один аргумент больше. Bash уже снял служебные кавычки до запуска программы, поэтому внутри `sys.argv` их нет. Так же ошибка проявится у `docker run` или `python train.py --weights 'my model.pt'`.

Переменная `params='--epochs 20'` не является готовым списком аргументов. Запись `"$params"` передаст **одно** значение с пробелом. Отказ от кавычек разбивает строку, но рискует раскрыть glob и испортить пути. Для надёжного массива аргументов используй Bash arrays:

~~~bash
args=(--epochs 20 --weights 'best model.pt')
printf '<%s>\n' "`{args[@]}"
~~~

Здесь `${args[@]}` подставляет элементы массива как отдельные аргументы; кавычки сохраняют пробелы внутри каждого элемента. Это стоит помнить, когда начнёшь писать оболочку вокруг обучения PyTorch.

Проверка: перед запуском предскажи число элементов, которое получит программа. Именно число аргументов, а не только напечатанная строка, объясняет поведение.
