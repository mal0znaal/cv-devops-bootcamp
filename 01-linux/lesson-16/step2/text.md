# Разреши выполнять свой скрипт

Создай `~/lab16/run.sh`. В первой строке `#!/usr/bin/env bash` — **shebang**: при прямом запуске он сообщает Linux, какой программой интерпретировать скрипт. `printf 'ready\n'` печатает слово ready и перевод строки.

Создай `~/lab16/run.sh`: 

```bash
#!/usr/bin/env bash
printf 'ready\n'
```

Сделай его исполняемым для владельца, но не для других (`chmod 700`). Запусти через `~/lab16/run.sh`.

**Не срезай угол:** объясни, чем отличается `bash run.sh` от `./run.sh` при отсутствии бита `x`.

---

Нажимай CHECK после собственной проверки результата.

## Исполнение и чтение — два разных права

Создай скрипт с shebang. Сначала проверь его синтаксис через `bash -n`, затем попытайся запустить напрямую до установки `x`. Сравни с `bash run.sh`: в последнем случае Bash уже сам является запущенным интерпретатором, поэтому бит исполнения самого файла не играет той же роли.

Установи `700` и проверь `stat -c %a`. Набери `./run.sh` из правильного каталога. Вопрос: как влияет `x` на каталог, в котором лежит скрипт?

**Где не срезать углы:** не используй `chmod 777` ради запуска.
