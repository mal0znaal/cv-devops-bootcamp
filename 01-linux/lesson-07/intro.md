# 07. Как читать текстовые файлы и наблюдать за логами

В Linux текст остаётся главным форматом многих конфигураций и диагностических сообщений. Разница между просмотром, фильтрацией и редактированием файла определяет, насколько быстро удастся найти причину ошибки.

## Что делает cat

`cat /etc/os-release` читает файл и пишет его содержимое в stdout. Название происходит от concatenate — соединение нескольких файлов в один поток. `cat a.txt b.txt` напечатает сначала первый, потом второй. Это не редактор.

`nano file.txt` — интерактивный редактор: ты видишь содержимое, меняешь его, сохраняешь. Обе программы обращаются к одним и тем же файловым интерфейсам, но решают разные задачи.

## Когда нужен less

Лог из десятков тысяч строк нельзя удобно изучать простым `cat`: терминал быстро заполнится выводом. `less file.log` открывает просмотр с прокруткой и поиском. Нажми `/ERROR`, затем `n` для следующих совпадений, `q` для выхода. Поиск действует внутри просмотрщика: не нужно перепечатывать команду и создавать временные файлы.

## head и tail

`head -n 5 file` печатает первые пять строк; `tail -n 5 file` — последние пять. `tail -f app.log` остаётся работающим и выводит новые строки по мере добавления. Это удобно, когда ты запускаешь сервис во втором терминале и наблюдаешь его лог.

При ротации логов файл может быть переименован и создан заново. `tail -f` продолжает следить за дескриптором, тогда как `tail -F` пытается повторно открывать файл по имени. Разница бывает существенной для настоящих серверов.

## Строки — это байты

В типичном текстовом файле строка заканчивается LF — байтом перевода строки `\n`. Windows часто использует CRLF — два байта `\r\n`. Поэтому Bash-скрипт с CRLF может ошибаться на строке shebang: интерпретатор воспринимает `\r` как часть пути.

`wc -l` считает **символы перевода строки**, а не «логические абзацы». Файл, содержащий слово `hello` без завершающего LF, может показать ноль строк в `wc -l`. Для упражнений полезно явно завершать строки переводом.

~~~bash
printf 'a\nb\n' > /tmp/two-lines.txt
wc -l /tmp/two-lines.txt
printf 'a\nb' > /tmp/no-final-newline.txt
wc -l /tmp/no-final-newline.txt
~~~

В конце каждого примера использовано перенаправление `>`. Оно создаёт или перезаписывает файл, а не дописывает его. Подробно разберём устройство потоков в следующем уроке.

## Байты и символы — не одно и то же

`wc -c file` считает байты, `wc -m file` — символы при учёте текущей локали. Буква «Я» в UTF-8 занимает больше одного байта. Поэтому размер файла в `ls -l` не обязан равняться количеству видимых символов.

## Как это связано с отладкой

Для небольшого файла `cat` подходит. Для длинного стектрейса — `less` с поиском. Для живого файла событий — `tail -f`. Для системного журнала `systemd` нужен `journalctl`, а для stdout контейнера — `docker logs`. Форма хранения определяет правильный инструмент.

## Эксперимент

Создай лог из пяти строк, открой его через `less`, найди одну внутреннюю строку и выйди. Проверь `head -n 2`, `tail -n 2` и `wc -l`. Затем запусти `tail -f`, допиши строку в файл из другого терминала (или останови слежение Ctrl+C, допиши и повтори). Разница между снимком и потоком новых данных станет наблюдаемой.

**Не срезай углы:** не заменяй работу с `less` постоянным использованием nano. Текстовый просмотрщик нужен для файлов, которые нельзя или не следует редактировать.
