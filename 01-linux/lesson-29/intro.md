# 29. Надёжные Bash-скрипты: условия, ошибки, pipefail и trap

Скрипт деплоя, который объявляет успех после неудачной доставки модели, опаснее скрипта, который сразу падает. Bash позволяет проверять каждый шаг, но правила выполнения и кодов выхода надо понимать точно.

## Условия проверяют статус команды

~~~bash
if [[ -f /etc/os-release ]]; then
    printf 'OS metadata found\n'
fi
~~~

`[[ ... ]]` проверяет условие; `-f` означает обычный файл, `-d` — каталог, `-n` — непустую строку. `if` оценивает статус команды или проверки. Это не отдельный тип Boolean, как в Python.

## -e, -u и pipefail

`set -e` прекращает исполнение при некоторых ошибках, но его поведение имеет исключения в условиях `if`, логических списках и других контекстах. Он **не заменяет** явную обработку ошибок.

`set -u` делает ошибкой использование неустановленной переменной. Поэтому скрипту стоит явно проверять обязательный аргумент, а не предполагать, что `$1` существует.

`set -o pipefail` изменяет статус конвейера: ошибка одной из команд может сделать ошибочным весь pipeline, даже если последняя команда отработала успешно. Но у `grep` код 1 может означать отсутствие совпадений — для одного сценария это нормальный результат, для другого аварийный.

## Почему || true иногда скрывает поломку

~~~bash
cp model.pt /srv/models/ || true
printf 'deployed\n'
~~~

`cp` могла не записать ни байта, но общий статус цепочки будет успешным. Так CI может признать развёртывание успешным. Игнорировать ошибку можно лишь тогда, когда предусмотрен конкретный допустимый отказ.

## trap и временные файлы

~~~bash
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT
printf 'sample\n' > "$tmp"
~~~

`mktemp` создаёт уникальный временный файл. `trap` регистрирует уборку при выходе. Это уменьшает риск конфликтов с чужими временными файлами. Кавычки вокруг `"$tmp"` защищают границы пути.

## Тестируй не только успешный вход

Скрипт `require-file.sh` обязан обрабатывать: существующий файл, отсутствующий файл, отсутствие аргумента и путь на директорию. Для каждого случая должно быть определено поведение и код выхода. Запуск одного успешного примера — слабый тест.

## Идемпотентность

`mkdir -p` допускает повторный запуск на уже созданном каталоге. Но если следующая команда дважды допишет одну строку в конфигурацию, весь скрипт **не** идемпотентен. Проверяй повторное выполнение целого сценария.

**Не срезай углы:** не добавляй `|| true` к падающей команде, пока не выяснил, что означает её код завершения.
