# Эксперимент: почему pipeline скрывает ошибку

Сначала проверь, что строка `NO_SUCH_STRING` отсутствует в `/etc/os-release`. Затем запусти следующий пример:

```bash
grep NO_SUCH_STRING /etc/os-release | wc -l
echo $?
```

Запиши код выхода, который показала вторая команда. Включи `set -o pipefail` и повтори обе команды. Почему теперь код отличается, хотя `wc -l` по-прежнему печатает ноль?

В `~/lab29/pipefail.txt` должны оказаться две строки формата:

```text
without=<код без pipefail>
with=<код с pipefail>
```

Угловые скобки означают место для **числа, полученного в твоём терминале**, а не буквальный текст для копирования.

Найди в Bash Reference Manual описание `pipefail`, затем объясни, почему ненулевой статус `grep` не всегда означает техническую поломку.

Если случайно изменил поведение своего интерактивного shell, вернуть стандартный режим можно через `set +o pipefail`.
