# 27. Переменные окружения и жизненный цикл shell

**Время:** ориентировочно 45–90 минут. Отдельные лабораторные создают отдельные Ubuntu VM.

## Откуда приложение получает конфигурацию

Переменные окружения — пары `KEY=value`, передаваемые новому процессу при запуске. `PATH`, `HOME`, `LANG`, `CUDA_VISIBLE_DEVICES`, `PYTHONPATH` — знакомые примеры. Переменная shell может быть **не экспортирована** и тогда дочерний `python3` её не увидит. `export KEY=value` разрешает наследование.

## Команды env и printenv

`env` выводит окружение, `printenv NAME` показывает одну переменную. Команда `MY_FLAG=1 python3 app.py` задаёт значение только для этого запуска, не обязательно изменяя переменную текущего shell после завершения. В CI job это один из основных способов передать настройки приложению.

## Где хранятся постоянные настройки

`~/.bashrc` обычно выполняется интерактивным non-login Bash, `~/.profile` может использоваться login shell, поведение зависит от способа запуска. Не стоит записывать секреты во все файлы подряд или принудительно подключать `.bashrc` из systemd unit. Для сервиса переменные настраивают через `Environment=` или `EnvironmentFile=` с правильными правами.

## Безопасность

Окружение не является полноценным сейфом: значения могут попасть в отладочный вывод, дампы и `/proc` при наличии прав. Для CI/CD использовать управляемое хранилище секретов и минимизировать логирование.

**Не срезай углы:** разберись, чем отличается `VAR=x`, `export VAR=x`, `VAR=x command`. [Bash environment](https://www.gnu.org/software/bash/manual/html_node/Environment.html).
