# 27. Переменные окружения: как Python получает конфигурацию

В Linux дочерний процесс получает определённый набор переменных окружения при запуске. Именно поэтому `CUDA_VISIBLE_DEVICES`, `PYTHONPATH`, `HTTP_PROXY` и другие параметры меняют поведение программы, хотя не передаются как обычные аргументы команды.

## Переменная Bash и environment процесса

~~~bash
MODE=training
printf '%s\n' "$MODE"
python3 -c 'import os; print(os.getenv("MODE"))'
~~~

Bash видит `MODE`, но Python может не увидеть: она ещё не экспортирована. После `export MODE` новые дочерние процессы получают её в окружении.

~~~bash
export MODE
python3 -c 'import os; print(os.getenv("MODE"))'
~~~

Текущий Python уже не может изменить переменные окружения родительского Bash простым `os.environ`: наследование направлено от родителя к дочернему процессу.

## Одноразовое окружение

~~~bash
MODE=production python3 -c 'import os; print(os.getenv("MODE"))'
~~~

Переменная назначена конкретному запуску. После завершения значение shell-переменной не обязательно изменилось на `production`. Это полезно для тестирования разных конфигураций без постоянного редактирования файлов.

## Почему .bashrc не управляет всеми сервисами

Интерактивный Bash читает определённые startup-файлы, а service unit запускает приложение в своём окружении. Поэтому строка `export MODEL_PATH=...` в `~/.bashrc` может работать для твоего терминала и не работать для `systemd`. Сервису переменные можно задать через `Environment=` и `EnvironmentFile=`; пути и права на файл важны.

## PATH — тоже переменная окружения

`PATH` задаёт директории поиска внешних команд, но программа с абсолютным путём, например `/usr/bin/python3`, не требует поиска по PATH. Неправильное окружение — типичная причина того, что команда доступна в SSH-сеансе и не найдена в CI job.

## Почему секреты — отдельная тема

Переменная окружения не является защищённым хранилищем. Она может попасть в диагностический дамп, лог или доступные с соответствующими правами интерфейсы процесса. Для production-секретов нужны ограниченные права, хранилища и политика логирования.

**Не срезай углы:** не пытайся исправить окружение сервиса массовым `source ~/.bashrc`. Сначала выясни, кто запускает приложение и какие переменные ему передаются.
