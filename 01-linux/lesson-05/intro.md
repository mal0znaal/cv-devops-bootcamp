# 05. Как shell раскрывает имена файлов: ls, glob и скрытые имена

Имя файла `train.log` и шаблон `*.log` — разные сущности. Первый является буквальным именем. Второй Bash может заменить на список совпадающих имён **до запуска программы**.

В этом эксперименте `touch filename` создаёт пустой файл, если его нет. Мы используем `touch` только как быстрый способ подготовить тестовые имена; подробности о создании файлов и временных метках будут в уроке 06.

## Что хранит каталог

Каталог сопоставляет имена с файловыми объектами. Команда `ls` обращается к файловой системе через библиотечные и системные интерфейсы и печатает список. `ls` не решает, какие файлы существуют: он получает данные от ОС.

~~~bash
mkdir -p ~/glob-lab
cd ~/glob-lab
touch train.log test.log notes.txt .env.example
ls
ls -a
~~~

Имя с начальной точкой по соглашению скрывается в обычном выводе `ls`. Это не защита: другой пользователь с соответствующими правами сможет прочитать файл независимо от точки.

## Разбираем вывод ls -l

Пример:

~~~text
-rw-r----- 1 student ml 8246 Oct 12 13:30 train.log
~~~

Первый символ обозначает тип объекта, далее три тройки прав владельца, группы и остальных. Число после прав связано с количеством жёстких ссылок. Затем идут владелец, группа, размер, время модификации и имя. `ls -lh` делает размеры удобнее для человека; `ls -la` включает скрытые файлы и подробные метаданные.

`ls` предназначен в первую очередь для людей. Надёжный скрипт не должен парсить его вывод как таблицу, потому что имена могут содержать пробелы, переводы строк и необычные байты. Для таких задач используют `find`, `stat` и специальные форматы вывода.

## Механизм filename expansion

Когда Bash встречает незакавыченный шаблон `*.log`, он ищет подходящие имена в текущей директории. `*` соответствует нулю или большему числу символов, `?` — одному символу, `[ab]` — одному символу из указанного набора. Это **globbing**, а не регулярные выражения.

~~~bash
printf '%s\n' *.log
printf '%s\n' '*.log'
printf '%s\n' ?est.log
~~~

В первой строке `printf` получает имена `test.log` и `train.log`. Во второй — буквальную строку `*.log`. В третьей — имена, в которых перед `est.log` стоит один символ, поэтому здесь совпадёт `test.log`.

По умолчанию `*` обычно не захватывает имена, начинающиеся с точки. Параметры `dotglob` и `nullglob` могут менять поведение Bash. Не нужно пока их устанавливать; достаточно помнить, что настройки shell влияют на результат шаблонов.

## Почему маски опасны в командах изменения файлов

Если в каталоге 200 файлов `*.log`, выражение `rm *.log` может превратиться в запуск `rm` с 200 аргументами. Это происходит ещё до старта `rm`. Удаление не «проверяет намерение» пользователя.

Для исследования шаблона сначала используй `printf '%s\n' *.log`. Для сложных задач лучше построить список путей через `find` и внимательно проверить его.

## Отличие glob от regex

Шаблон `*.log` в Bash означает «любая последовательность символов, затем точка и log». В регулярном выражении `.*\.log$` используется совершенно другая грамматика: `.` — любой символ, `*` повторяет предыдущее выражение, `\` экранирует точку, `$` обозначает конец строки.

Смешение glob и regex — одна из частых причин, по которым фильтр логов выбирает неожиданные файлы.

## Эксперимент на пяти файлах

Создай `a.log`, `b.log`, `c.txt`, `.hidden.log` и `test.log`. Выполни `printf '%s\n' *.log` и проверь, попадёт ли скрытый файл. Затем сделай `printf '%s\n' .*.log`. Объясни, почему результаты отличаются.

**Не срезай углы:** разбери разницу кавычек на этой маленькой директории до экспериментов с реальными датасетами, checkpoint-файлами и логами.
