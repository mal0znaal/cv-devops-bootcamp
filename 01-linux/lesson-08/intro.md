# Урок 8. Потоки Unix: stdin, stdout, stderr, >, >>, pipe

**Ориентир:** 60–90 минут. Лабораторная открывает новую временную Ubuntu VM. Не изменяй ничего за пределами указанных тестовых путей.

## Самая важная конструкция shell

У процесса обычно есть три стандартных файловых дескриптора: **0 — stdin** (ввод), **1 — stdout** (обычный вывод), **2 — stderr** (диагностика и ошибки). Обычно все связаны с терминалом. `echo hello` печатает текст в stdout. Это не файловая операция: запись в файл организует Bash.

## Перенаправления делает оболочка

Когда вводишь `echo hello > out.txt`, **shell до запуска команды** открывает файл и направляет в него stdout. `>` создаёт файл или **обнуляет существующий**. `>>` открывает его для добавления в конец. Два раза `>` подряд — значит потерять первую запись. Для тебя это важно, когда сохраняешь логи и артефакты выполнения.

## Отдельный поток ошибок

Команда `ls /missing` обычно пишет сообщение в stderr, а не stdout. Поэтому `ls /missing > normal.txt` не перехватит ошибку. Нужен `2> errors.txt`; запись `2>&1` направляет stderr туда, куда stdout уже направлен **в момент применения перенаправления**. Порядок операций имеет значение.

## Pipe соединяет два процесса

`producer | consumer` отправляет stdout первой команды на stdin второй: например, `printf 'a\nb\n' | wc -l`. Не нужен промежуточный файл. `>` направляет в файл, `|` — другой программе. stderr по умолчанию не смешивается с stdout.

## echo против printf

`echo` годится для простых строк; его обработка `-n` и escape-символов в разных реализациях отличается. `printf '%s\n' first` явно задаёт формат и новую строку, поэтому для скриптов часто удобнее. Часть действий выполняет оболочка, часть — сама программа, и это различие мы повторим при обсуждении `sudo`.

## Ловушка с sudo

`sudo echo text > /root/file` часто не работает у обычного пользователя: `sudo` повышает права **для echo**, а открытие файла оператором `>` делает текущий shell без повышенных прав. На рабочем сервере нельзя лечить это бездумным запуском всего терминала от root.

**Здесь нельзя срезать углы:** нарисуй для себя три стрелки stdin/stdout/stderr и попробуй проговорить, что делают `>`, `>>`, `2>` и `|`. Без этого будут непонятны логи контейнеров и Bash.
